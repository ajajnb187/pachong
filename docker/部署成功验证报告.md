## 四、已解决的关键问题

### 4.1 问题：Hive Metastore Schema重复初始化失败
**错误信息**:
```
Error: ERROR: relation "BUCKETING_COLS" already exists
Schema initialization FAILED! Metastore state would be inconsistent !!
```

**解决方案**:
修改`init-metastore.sh`脚本，添加schema检查逻辑：
```bash
if /opt/hive/bin/schematool -dbType postgres -info > /dev/null 2>&1; then
    echo "Schema已存在，跳过初始化"
else
    echo "Schema不存在，开始初始化..."
    /opt/hive/bin/schematool -dbType postgres -initSchema
fi
```

### 4.2 问题：Hadoop Proxy User权限错误
**错误信息**:
```
User: root is not allowed to impersonate anonymous
```

**解决方案**:
在`hadoop.env`中添加root用户代理配置：
```bash
CORE_CONF_hadoop_proxyuser_root_hosts=*
CORE_CONF_hadoop_proxyuser_root_groups=*
```

### 4.3 问题：PostgreSQL vs MySQL选择
**决策**:
- 使用PostgreSQL 11-alpine作为Hive Metastore
- MySQL 8.0仅用于业务数据库
- 原因：bde2020/hive镜像对PostgreSQL支持更好，避免版本兼容问题

## 六、数据上传流程

### 6.1 自动上传（推荐）
爬虫脚本`tourism-flask/tasks/crawl_task_v2.py`已配置自动上传到HDFS。

### 6.2 手动上传示例
```bash
# 1. 将本地文件复制到容器
docker cp 本地数据.jsonl namenode:/tmp/

# 2. 上传到HDFS
docker exec namenode hdfs dfs -put /tmp/本地数据.jsonl \
  /tourism/data/spots/dt=20241213_150000/

# 3. 修复Hive分区
docker exec 9b63938f4d15_hive-server /opt/hive/bin/beeline \
  -u jdbc:hive2://localhost:10000 -e "
  USE tourism_db;
  MSCK REPAIR TABLE scenic_spots;
  MSCK REPAIR TABLE fuzhou_reviews;
"
```
