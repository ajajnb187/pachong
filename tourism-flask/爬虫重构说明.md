# 爬虫系统重构说明 V2

## 🎯 重构目标

解决原有爬虫的核心问题，实现景点数据和评论数据的正确分离，对应Hive两张表的设计。

## ❌ 原有问题

1. **只爬10个景区**：爬虫只爬取第1页（10个景区）就停止
2. **数据混淆**：把景点基本信息当作"官方评论"存入reviews表
3. **表结构不匹配**：数据结构与Hive表设计不一致

## ✅ 新架构设计

### Hive表结构

```sql
-- 1. 景点基本信息表
CREATE EXTERNAL TABLE IF NOT EXISTS tourism_db.scenic_spots (
    scenic_spot STRING COMMENT '景点名称',
    city STRING COMMENT '城市',
    review_count BIGINT COMMENT '评论总数',
    avg_rating DOUBLE COMMENT '平均评分',
    last_review_date STRING COMMENT '最后评论日期'
)
ROW FORMAT SERDE 'org.apache.hive.hcatalog.data.JsonSerDe'
STORED AS TEXTFILE
LOCATION '/tourism/data/spots/';

-- 2. 评论数据表
CREATE EXTERNAL TABLE IF NOT EXISTS tourism_db.fuzhou_reviews (
    scenic_spot STRING COMMENT '景点名称',
    city STRING COMMENT '城市',
    rating DOUBLE COMMENT '评分',
    visitor_name STRING COMMENT '游客名',
    review_content STRING COMMENT '评论内容',
    travel_date STRING COMMENT '旅游日期',
    review_date STRING COMMENT '评论日期',
    data_source STRING COMMENT '数据来源',
    crawl_time STRING COMMENT '爬取时间'
)
ROW FORMAT SERDE 'org.apache.hive.hcatalog.data.JsonSerDe'
STORED AS TEXTFILE
LOCATION '/tourism/data/reviews/';
```

### 爬虫执行流程

```
阶段1: 爬取所有福州景点基本信息
├── 循环爬取景点列表API（所有页，直到无数据）
├── 提取景点：名称、城市、平均评分
└── 保存到: spots_福州_任务ID_时间.jsonl

阶段2: 为每个景点爬取用户评论  
├── 遍历所有景点
├── 调用评论API获取真实用户评论
├── 提取：景点名、评分、游客名、内容、日期
└── 保存到: reviews_福州_任务ID_时间.jsonl
```

## 🚀 使用方法

### 1. 启动爬虫任务

```bash
# 方式1: 通过API启动（推荐）
curl -X POST http://localhost:5000/api/admin/crawl/fuzhou \
  -H "Content-Type: application/json" \
  -d '{
    "target_count": 500,
    "crawl_mode": "full"
  }'

# 方式2: 限量爬取
curl -X POST http://localhost:5000/api/admin/crawl/fuzhou \
  -H "Content-Type: application/json" \
  -d '{
    "target_count": 200
  }'
```

### 2. 查看任务状态

```bash
# 查询任务进度
curl http://localhost:5000/api/crawler/status/{task_id}

# 查看任务列表
curl http://localhost:5000/api/crawler/tasks?page=1&page_size=10
```

### 3. 数据导入Hive

```bash
# 1. 上传景点数据到HDFS
docker exec namenode hdfs dfs -put -f \
  /path/to/spots_福州_*.jsonl \
  /tourism/data/spots/

# 2. 上传评论数据到HDFS
docker exec namenode hdfs dfs -put -f \
  /path/to/reviews_福州_*.jsonl \
  /tourism/data/reviews/

# 3. 在Hive中查询
docker exec -it hive-server beeline -u jdbc:hive2://localhost:10000 \
  -e "SELECT COUNT(*) FROM tourism_db.scenic_spots;"

docker exec -it hive-server beeline -u jdbc:hive2://localhost:10000 \
  -e "SELECT COUNT(*) FROM tourism_db.fuzhou_reviews;"
```

### 联合分析（两表JOIN）

```sql
-- 示例：统计每个景区的评论数和平均评分
SELECT 
    s.scenic_spot,
    s.avg_rating AS api_rating,
    COUNT(r.scenic_spot) AS review_count,
    AVG(r.rating) AS actual_avg_rating
FROM tourism_db.scenic_spots s
LEFT JOIN tourism_db.fuzhou_reviews r ON s.scenic_spot = r.scenic_spot
GROUP BY s.scenic_spot, s.avg_rating
ORDER BY review_count DESC
LIMIT 10;
```

## ⚠️ 注意事项

1. **编码问题**：所有JSONL文件使用UTF-8编码
2. **数据量控制**：全量爬取建议设置 `reviews_per_spot=20`，避免请求过多被封
3. **爬取间隔**：代码已内置延迟（2秒/页），请勿修改
4. **Hive表更新**：重新爬取后需要刷新Hive表：`MSCK REPAIR TABLE tourism_db.scenic_spots;`
