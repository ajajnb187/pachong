# 福州旅游大数据分析系统 - 使用说明

## 一、系统架构

本系统采用Docker容器化部署，包含以下核心组件：

| 组件 | 版本 | 作用 | 端口 |
|------|------|------|------|
| Hadoop NameNode | 3.2.1 | HDFS主节点，存储数据 | 9870(Web), 9000(RPC) |
| Hadoop DataNode | 3.2.1 | HDFS数据节点 | 9864 |
| Hive Metastore | 2.3.2 | Hive元数据服务 | 9083 |
| HiveServer2 | 2.3.2 | Hive查询服务 | 10000 |
| PostgreSQL | 11 | Hive元数据库 | 15432 |
| Redis | 7 | 缓存服务 | 6379 |
| MySQL | 8.0 | 业务数据库 | 23306 |

**注意**: Hive使用PostgreSQL作为元数据库（metastore），这是推荐的生产环境配置，不需要MySQL。

## 二、一键部署

### Windows系统

双击运行 `deploy.bat` 脚本即可完成全部部署。

或在命令行执行：
```cmd
cd docker
deploy.bat
```

### Linux/Mac系统

```bash
cd docker
chmod +x deploy.sh
./deploy.sh
```

## 三、手动部署步骤

如果需要手动控制部署过程：

```bash
# 1. 停止旧环境
docker-compose down -v

# 2. 启动所有服务
docker-compose up -d

# 3. 等待60秒让服务完全启动
# 然后创建HDFS目录
docker exec namenode hdfs dfs -mkdir -p /tourism/data/spots
docker exec namenode hdfs dfs -mkdir -p /tourism/data/reviews
docker exec namenode hdfs dfs -chmod -R 777 /tourism
```

## 四、数据上传流程

### 4.1 自动上传（推荐）

爬虫任务会自动将数据上传到HDFS：

```python
# tourism-flask/tasks/crawl_task_v2.py 已配置自动上传
# 执行爬虫后数据自动存储到:
# /tourism/data/spots/dt=YYYYMMDD_HHMMSS/
# /tourism/data/reviews/dt=YYYYMMDD_HHMMSS/
```

### 4.2 手动上传

```bash
# 将本地文件复制到Docker容器
docker cp 本地文件.jsonl namenode:/tmp/

# 上传到HDFS
docker exec namenode hdfs dfs -put /tmp/本地文件.jsonl /tourism/data/spots/dt=20251213_150000/
```

### 4.3 发现新分区

上传数据后，需要让Hive发现新分区：

```bash
docker exec hive-server /opt/hive/bin/beeline -u jdbc:hive2://localhost:10000 -e "
USE tourism_db;
MSCK REPAIR TABLE scenic_spots;
MSCK REPAIR TABLE fuzhou_reviews;
"
```

## 五、Hive数据查询

### 5.1 连接Hive

```bash
# 方式1: 在容器内使用beeline
docker exec -it hive-server /opt/hive/bin/beeline
!connect jdbc:hive2://localhost:10000

# 方式2: 直接执行SQL
docker exec hive-server /opt/hive/bin/beeline -u jdbc:hive2://localhost:10000 -e "SHOW DATABASES;"
```

### 5.2 常用查询示例

```sql
-- 切换数据库
USE tourism_db;

-- 查看所有表
SHOW TABLES;

-- 查看分区
SHOW PARTITIONS scenic_spots;

-- 查询景点数据
SELECT * FROM scenic_spots LIMIT 10;

-- 景点评分排行
SELECT scenic_spot, AVG(comment_score) as avg_score
FROM scenic_spots
GROUP BY scenic_spot
ORDER BY avg_score DESC
LIMIT 20;

-- 游客评论分析
SELECT 
    scenic_spot,
    AVG(rating) as avg_rating,
    COUNT(*) as review_count
FROM fuzhou_reviews
GROUP BY scenic_spot
ORDER BY review_count DESC;

-- 按月份统计游客量
SELECT 
    SUBSTR(travel_date, 1, 7) as month,
    COUNT(*) as visitor_count
FROM fuzhou_reviews
WHERE travel_date IS NOT NULL
GROUP BY SUBSTR(travel_date, 1, 7)
ORDER BY month;
```

## 六、常见问题

### Q1: 服务启动失败？

```bash
# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs hive-metastore
docker-compose logs hive-server

# 重启服务
docker-compose restart hive-metastore hive-server
```

### Q2: 无法连接HiveServer2？

```bash
# 检查HiveServer2是否启动
docker exec hive-server netstat -tuln | findstr 10000

# 如果没有输出，等待服务启动（首次启动需要较长时间）
# 或查看日志排查问题
docker-compose logs hive-server
```

### Q3: 数据上传后查不到？

```bash
# 修复分区元数据
docker exec hive-server /opt/hive/bin/beeline -u jdbc:hive2://localhost:10000 -e "
MSCK REPAIR TABLE tourism_db.scenic_spots;
MSCK REPAIR TABLE tourism_db.fuzhou_reviews;
"

# 手动添加分区
docker exec hive-server /opt/hive/bin/beeline -u jdbc:hive2://localhost:10000 -e "
ALTER TABLE tourism_db.scenic_spots ADD IF NOT EXISTS PARTITION (dt='20251213_150000');
"
```

### Q4: 如何清空所有数据重新部署？

```bash
docker-compose down -v
docker volume prune -f
docker-compose up -d
```

## 七、系统维护

### 7.1 备份数据

```bash
# 备份HDFS数据
docker exec namenode hdfs dfs -get /tourism /backup/hdfs-tourism

# 备份Hive元数据
docker exec hive-metastore-postgresql pg_dump -U hive metastore > metastore_backup.sql
```

### 7.2 监控服务

```bash

docker stats

# 查看HDFS状态
docker exec namenode hdfs dfsadmin -report

# 查看Hive表信息

DESCRIBE FORMATTED tourism_db.scenic_spots;
"
```

### 7.3 日志管理

```bash

docker-compose logs -f hive-server

# 导出日志
docker-compose logs > system.log
```

## 九、技术支持

### 服务架构说明

本系统基于Apache官方推荐的Hadoop + Hive架构：

1. **Hadoop HDFS**: 分布式文件系统，存储海量数据
2. **Hive**: 数据仓库工具，提供SQL查询能力
3. **PostgreSQL Metastore**: Hive元数据存储，管理表结构和分区信息

### 为什么使用PostgreSQL而不是MySQL？

- bde2020/hive镜像默认支持PostgreSQL
- PostgreSQL在并发和事务处理上更稳定
- Apache Hive官方推荐PostgreSQL作为生产环境metastore
